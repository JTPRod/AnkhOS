# KemeticReference — initial scaffold

## Included

- Official Identity/SQLite Blazor template generated by Setup.ps1.
- Data-driven home page with case-insensitive name/alternate-name search.
- Shared deity pages, section links, source rendering, and error states.
- Reference models and five explicitly labeled development placeholders.
- Profile, favorite, post, and report models for later EF integration.
- Clearly labeled placeholder pages for milestone B/C workflows.

## Run

Open KemeticReference.csproj in Visual Studio with compatible .NET 10 tooling. Run using its HTTPS launch profile. Or, from the project directory:

```powershell
dotnet build
dotnet run
```

Open the localhost URL printed by dotnet. If local HTTPS is not trusted, run `dotnet dev-certs https --trust` on your computer. The generated launch settings/configuration are retained.

## What is not complete

No community/profile/favorite CRUD services or database mappings are implemented yet. Application models are not added to ApplicationDbContext, and no application migrations are generated. Template Identity files and migrations are retained, but registration/email confirmation must be configured and tested before use. Do not publish this starter as a completed application. The template may expose development-only confirmation links: replace this with a local email sink before account testing and actual email delivery before deployment.

## Next implementation task

Extend the generated Identity ApplicationDbContext with application DbSets, unique favorite pairs, one-to-one profiles, user foreign keys and explicit deletion behavior. Configure a compatible IDbContextFactory without conflicting option lifetimes; preserve Identity's scoped context registration. Then generate/apply migrations and implement authentication-derived user ownership in services before enabling write forms.

## Check the reference milestone

1. Open home: five placeholder cards appear.
2. Search `anu`, then ` ANU `: Anubis appears.
3. Search an unknown name: an empty-results message appears.
4. Open a deity: empty sections clearly state no reviewed information is available.
5. Visit `/deities/unknown`: not-found state appears.
6. Add a sixth JSON record with a unique ID and restart the app: it appears automatically.
7. Check mobile layout at 360 pixels.

DeityService caches the catalog for the application lifetime: restart after editing JSON. Add sourced entries and remove IsPlaceholder only after review. No religious claims are invented in the starter.
